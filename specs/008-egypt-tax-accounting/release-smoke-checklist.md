# DaftarX — Pre-Release Smoke Checklist

**P0.4 from the post-MVP roadmap.** A 30-minute browser smoke that
catches obvious regressions before every release. Real coverage comes
from the Playwright suite (P0.5); this checklist is the human gate
between "build green" and "ship to customer."

## How to use

1. Deploy the release candidate to a fresh VM (or `localhost` after
   `dotnet publish` + `deploy.ps1`).
2. Open Chrome / Edge **in incognito** so cached state doesn't mask bugs.
3. Walk the 10 paths below in order. Each row should pass without errors.
4. If anything fails, abort the release. Open a bug, fix, restart smoke.

> **Time budget:** 30 minutes for a clean run. If it takes longer than
> 45 minutes, the checklist is too long — split into critical/extended.

---

## Test data assumed

The "fresh seed" profile (`P0.2`) populates:
- 1 admin user (`admin@daftarx.local` / `TempP@ssw0rd!2026`, must change)
- 4 default VAT categories (Standard 14% / Reduced 5% / Zero-rated / Exempt)
- 5 demo customers, 5 demo suppliers, 20 demo items
- 30 sample posted invoices spanning 3 months

Smoke runs against this profile. Production DB is NOT used for smoke.

## The 10 paths

| # | Path | Click flow | Expected result |
|---|---|---|---|
| 1 | **Login** | `/login` → enter `admin@daftarx.local` + temp password → submit | Forced redirect to `/password/change`. Brand mark visible (DX gradient + "DaftarX"). |
| 2 | **Force-change password** | New password (12+ chars) twice → submit | Redirect to `/`. Dashboard renders. |
| 3 | **Dashboard loads** | (continued from #2) | Period banner visible. 5+ KPI cards render. Activity feed shows seed data. Sidebar has 6 sections. |
| 4 | **Language toggle** | Click "English" in topbar | URL shows `/set-culture?...` then redirects back. Page text now in English; sidebar nav still grouped same way. Click "العربية" to flip back. |
| 5 | **Create + post sales invoice** | `/invoices/new` → pick customer + item → save draft → submit for approval (FR-026) → approve → post | Invoice moves Draft → Submitted → Approved → Posted. Document number assigned. ETA submission row created with PENDING status. |
| 6 | **Sales invoice detail page** | Open the invoice from #5 | Customer, lines, totals all match. **CorrectionAdvisor (P1.9) renders** with "Not yet accepted by ETA" banner. ETA submission section shows Pending. |
| 7 | **VAT report** | `/reports/vat-monthly` → pick current month → Run | Output VAT total > 0. Input VAT shows. Net payable = output − input. Drill-down link on a row navigates to the invoice. |
| 8 | **Penalty Shield** | `/penalty-shield` | Tier banner visible (Clear/Warning/Tier 2/Tier 3 — depends on seed). 5 KPI cards. Work queue table or "All clear" message. Educational footer with regime table. |
| 9 | **Certificates** | `/certificates` | At minimum the DaftarX HTTPS cert appears (generated by setup-https.ps1). Cert thumbprint shown. Days-until-expiry column populated. |
| 10 | **Audit log + chain integrity** | `/audit-log` → click "Verify chain integrity" | Verification returns "valid" with N entries scanned. No 500 errors. Chain check completes within 5 seconds for ≤10K entries. |

## Visual checks (RTL + branding)

While clicking through, verify:

- [ ] Sidebar is on the **right** in Arabic, **left** in English
- [ ] Topbar shows company name + current period + lang toggle + user avatar
- [ ] No emoji used as main UI icons (SVG icons only). Acceptable: emoji in `<h1>` / KPI labels for visual punch.
- [ ] Active nav item has navy `::before` accent bar
- [ ] All KPI cards have a top color stripe (`::before`)
- [ ] Buttons hover-lift (translateY(-1px))
- [ ] Forms have indigo focus ring
- [ ] Status badges (state-posted, eta-pending, etc.) are pill-shaped with semantic colors

## Error-state checks

- [ ] Logging out (`/logout`) redirects to login page (not a blank page)
- [ ] Visiting `/items` while no VAT categories exist auto-seeds the 4 defaults (P0.2 + lazy-seed)
- [ ] Closing browser mid-session and re-opening still requires login (cookie expiry working)
- [ ] Bad password 5+ times locks the account (FR-039)

## Browser matrix

Run the smoke in **at least one** of:
- Edge (latest) on Windows 11
- Chrome (latest) on Windows 10/11

Firefox + Safari are nice-to-haves but not blockers — both have minor RTL grid quirks we don't optimize for.

---

## After the smoke

If all 10 paths pass:
1. Tag the release: `git tag v1.x.x && git push --tags`
2. Build the customer installer: `iscc installer-inno/daftarx-setup.iss`
3. Upload `publish/DaftarX-Setup.exe` to the customer download channel
4. Update `specs/008-egypt-tax-accounting/post-mvp-roadmap.md` "completed" status

If any path fails:
1. **Don't ship.** File the bug.
2. Fix → redeploy → re-run smoke from path 1 (full re-run, not partial — regressions in fixes are common).
